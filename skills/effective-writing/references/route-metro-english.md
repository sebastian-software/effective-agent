# Route: Metro English

Use this route by default when drafting or revising short communication to
teammates: Slack and chat messages, GitHub, GitLab, Linear, and Jira comments,
PR reviews and approvals, async updates, and internal announcements. It applies
when another workflow produces the message, even without a rewrite or style
request. The default register is relaxed US professional English; preserve the
repository's language and the channel's required formality.

Metro English names a specific register within this discipline, not a
separate discipline. Resolve the former name "metro-english" to this route.

## Read

[Metro English](metro-english.md) — voice target, rewrite rules, patterns to
avoid, per-channel presets, worked examples, and the output contract.

The long-form [nonfiction assignment contract](nonfiction-assignment.md) does
not apply here. A Slack message has no thesis, evidence register, or revision
sequence; loading it would slow the rewrite down without improving it.

## Apply

- Preserve intent, facts, names, constraints, and the decision. Keep the
  message as short as the reader needs to act; cut padding from a source draft
  unless the user asked for detail.
- Preserve the status of related actions. Drafting an approval does not mean it
  was submitted; a team update must not report that approval as completed.
- Make the ask obvious: what should happen, who is blocked, what decision is
  needed.
- Stop when a named controlled-language contract governs the artifact
  (ASD-STE100, Simplified Technical English, an adopted controlled-English
  profile). Hand that artifact to `effective-delivery` and keep the team
  message about it here.
- Return only the requested message by default.
